Rotting Oranges

Each minute, every fresh orange that touches a rotten one (up, down, left or right) rots too. How many minutes until nothing is fresh? If some orange can never rot, the answer is -1.

  • 0 empty cell
  • 1 fresh orange
  • 2 rotten orange

The slow idea first

Simulate it literally. Each minute, scan the whole grid and rot every fresh orange that has a rotten neighbour. Use a copy of the grid so oranges that rot this minute do not spread in the same minute. Stop when a scan changes nothing.

That is correct, but wasteful. In a long snake of oranges the rot takes about n·m minutes, and every minute re-scans n·m cells. The cost grows like (n·m)². Most of those scans look at oranges that cannot possibly change, because only an orange that rotted in the previous minute can rot a new one.

The insight

  • Rot spreads in waves

    Every rotten orange acts at the same moment. The number of minutes is the number of waves, not the number of oranges.

  • A wave is a BFS level

    The oranges that rot at minute k are the fresh ones that are exactly k steps from the nearest rotten orange. Breadth-first search visits cells in order of distance, so each level of the search is one minute.

  • Start from all rotten oranges at once

    Put every rotten orange into the queue before the search begins. Each fresh orange then receives the distance to its nearest rotten neighbour automatically. Running a separate search from each rotten orange would repeat work and still need a minimum at the end.

So the answer is the largest of those distances, taken over every orange that can rot. If a fresh orange has no path to a rotten one, return -1.

Why not DFS? Depth-first search follows one route as deep as it can, so it often reaches a cell by a long route first and stamps it with a late time. BFS is the tool for shortest distance on an unweighted grid.

Complexity

O(n·m)

Time.

An orange is marked rotten at the moment it is pushed, so it enters the queue at most once. Each queued orange checks four neighbours, and the first scan visits every cell once.

O(n·m)

Space.

The queue can hold a large share of the grid, for example when most cells start rotten. The grid itself is changed in place, so copy it first if the caller needs the original.

Mistakes to watch for

  • Marking at pop instead of at push. Several neighbours can queue the same orange in one minute, and the fresh count then drops more than once for it.
  • Calling q.size() inside the loop. The size changes as you push, so next-minute oranges leak into this minute. Read it once before the inner loop.
  • One minute too many. The last level has nothing left to rot, yet a naive counter still adds a minute for it. The fresh > 0 check in the loop condition prevents that.
  • Forgetting the empty-grid cases. A grid with no fresh oranges returns 0, even when it has no rotten ones either. A grid with a fresh orange and no rotten one returns -1.
